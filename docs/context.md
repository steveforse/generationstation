# Project context

Updated: 2026-11-28. This file is the current state: what the project is, what has been decided and what is open. Measurements and per-model set-up facts are in `docs/model-notes.md`; the architecture and implementation plan are in `docs/plan.md`; the running list of open work is `docs/todo.md`.

## What it is

Generation Station (formerly ModelDock) is a web dashboard and host API for running AI models on one computer and using them: chat with a text model that can also make things, songs, pictures, speech, video clips, transcripts, decisions and meeting notes. The browser shows the dashboard; the host API, the database and the models run on the computer that has the hardware. Planned: the web app moves to the owner's Proxmox homelab server and calls the host, which keeps running the models.

## Requirements and preferences

- The owner uses it at home and at work. Every model records its licence with a verdict (work use, conditions to check, or personal use only), and the Models page filters by it. A primary user who is not technical wants to make music, pictures and video.
- Explicit start and stop for every model, a choice of graphics card where there is one, live RAM and VRAM, and a refusal to start when capacity cannot be established. The host API makes that check, never the browser, and unknown or stale capacity never allows a start.
- The runtime is Generation Station's own, independent of ComfyUI (ComfyUI and biniou were evaluated on 2026-11-11 and rejected: too complex, and biniou lacks the target models). llama.cpp is rejected as a runtime.
- Work data may go to the work LiteLLM and Bedrock gateway. Nothing else is assumed to be allowed to leave the computer.
- Model weights, generated outputs, credentials and runtime caches stay out of source control.

## Decisions

- **Stack.** React, TypeScript and Vite for the frontend; Python and FastAPI for the host API and process supervisor (accepted 2026-10-08). PostgreSQL 17 in Docker with a persistent volume; SQLAlchemy 2 and Alembic (schema changes only through Alembic migrations, now at 0010). One scheduler owner per database (an advisory lock), and model start and stop operations are serialized.
- **Plugins and workers** (accepted 2026-11-11). Each kind of runtime is a plugin in `backend/generationstation/plugins/`; media models run in workers (`workers/`) under their own Python environments, speaking one HTTP protocol (`docs/plugins.md`). Which models a host offers is its local `runtimes.json` (ignored by Git; `runtimes.example.json` for the Windows desktop and `runtimes.mac.example.json` for the Mac are the templates). Presets, memory estimates, licences and quality scores live in that file.
- **Hosts and access.** Each saved host in the browser has its own connection, address and bearer token, kept in that browser's storage ("remember on this device"). The menu works on one host at a time. Tailscale gives remote access; the API listens on 127.0.0.1 in development. An unauthenticated request returns 401.
- **Results** are files on the host with a record of the settings the model actually used, a thumbnail, and a detail view with reuse, download and delete. A job can be cancelled while queued or running.
- **Consolidated pages.** Models of one kind share one page with a dropdown over those running (Images, Music, Speech, Video, Transcription, Decision, Chat). What the person typed moves with them when they change the model, by role, and each model declares what it can take. Each kind has one chat tool (`make_image`, `make_song`, `speak`, `make_video` and `transcribe`). The Models page, Overview and sidebar use the same sections: Chat, Decision, Images, Music, Speech, Transcription, Video, then Workflows (Meeting notes, which is a workflow rather than a model). The Models page has Local, Hosted and Workflows tabs.
- **Chat.** Conversations live on the host and a turn runs on the host, so it finishes if the browser leaves. The model may start jobs on any running model without asking and may start and stop models with a check of the memory estimate first (it refuses to stop the model answering it or one with jobs). Tools: host status, start and stop a model, read a log, find earlier results, list and cancel jobs, show results, read a web page (public addresses only, and web text is treated as information, never instructions) and search the web through a SearXNG address set in Host settings. Pictures and clip thumbnails go to the model only for the current turn. Thinking levels are each model's own, shown only where the model takes them.
- **Hosted chat models** (optional, 2026-11-28). Providers (an OpenAI-compatible gateway such as LiteLLM) are set up on the Host settings page: a name, the gateway's address and the name of the environment variable that holds its token. The token is read from the process environment or `.env` and is never stored by the app. Models come from the gateway's `/v1/models`, are ticked on the Hosted tab of the Models page and appear in the Chat as `<provider>:<model>`. They always count as ready and use no local memory. A `providers` section in `runtimes.json` still works. Tested against the work gateway: streaming, tool calls and reasoning effort low to high work. OpenCode as a source was dropped because OpenCode does not discover a custom provider's models; the owner will revisit on the Windows desktop.
- **Help assistant.** A round button on every page except Chat opens a small chat (one ongoing thread, "Start over", "Open in Chat"). It gets `backend/generationstation/assistant_guide.md`, a list of the models generated from the live catalog (with the hosted ones) and the page the person is on. It runs on the running local model marked `assistant` in the catalog, else any running chat model, else a hosted model, with thinking off.
- **Licences.** Each entry's verdict is a plain-words reading, not legal advice. MiniMax H3 may not be used in the EU, the UK, South Korea or the United States, so it is personal use only and never for colleagues. Qwen Image 2.1 is under the Qwen Research License (non-commercial).
- **Documentation.** Repository Markdown is authoritative. `docs/context.md` holds the current state, `docs/model-notes.md` the measurements and `docs/todo.md` what is open.

## Hosts

**Windows desktop (the deployment target).** AMD Ryzen 9 9950X3D (16 cores, 32 threads); about 125.5 GiB RAM; NVIDIA RTX 5090 (32 GB, index 0) and RTX 4080 (16 GB, index 1, which drives the display, so its free memory moves with desktop and game use); Windows 11. Model weights are on `D:\ai\models`, Python environments on `C:\ai\envs`, Basalt in `C:\ai\basalt-win` (and 0.5.5 in `C:\ai\basalt-v0.5.5`), Strata in `C:\ai\strata`, generated files on `D:\ai\outputs`. The Drama 3 speech model runs in WSL Ubuntu, which needs `D:` mounted by hand after a WSL restart. Catalog: DeepSeek V4.1 Flash, Qwen3.8 Flash-Next and Inkling 2 Mini (text), YuE2 (songs), Qwen Image (pictures), MiniMax H3 (clips and pictures, with an AI upscale to 1080p), OmniVoice, Qwen3-TTS and Drama 3 (speech) and Meeting notes. The Music, Images, Speech, Video, Transcription and Decision pages have been checked on the Mac only; the Windows desktop's use of them is untested. Do not use another machine's hardware as a substitute for this inventory.

**Mac (development laptop).** Apple M5 Max with 64 GB of unified memory; each worker runs under a soft MLX limit of about 26 GiB. Weights, environments and tools are under `~/ai`. Catalog (`runtimes.mac.example.json`): text (Qwen3.8 27B, Qwen3.8 Flash-Next, Tencent Hy4-Flash, Inkling 2 Mini), pictures (Qwen Image 2.1 and 2512, Z-Image Turbo), songs (YuE2, ACE-Step 1.5, MiniMax Music 3), speech (Qwen3-TTS, OmniVoice, Drama 3, S2 Pro, Breeze TTS 2), video (Wan 2.2, LongCat, FastMetal, LTX-2.5, H3), transcription (Qwen3-ASR, Whisper large-v3-turbo, Parakeet TDT v3), decision (pplx-decider 27B, H2O-Lightning 4B, Torchcast 4B and 31B) and Meeting notes. Setup is in `docs/setup-macos.md`.
